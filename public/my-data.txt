DocuMind AI – 100-Line Project Knowledge Base

DocuMind AI is an AI-powered documentation generator designed for backend developers.

The system automates Swagger (OpenAPI) generation from uploaded backend source code.

It primarily accepts a .zip file containing server-side code as input.

The AI scans all backend files recursively within the zip archive.

It identifies route handlers, controllers, endpoints, request/response schemas, and middleware.

The core purpose is to eliminate manual Swagger documentation efforts.

It outputs a well-structured JSON file that conforms to the Swagger (OpenAPI 3.0) standard.

That JSON can directly be used with tools like Swagger UI or Postman.

DocuMind AI is designed for frameworks like Node.js (Express.js), Flask, Django REST, and FastAPI.

It also plans to support Java Spring Boot and .NET Core in upcoming releases.

The system extracts metadata such as HTTP methods, URL paths, and function docstrings.

It uses static code analysis to understand function signatures and annotations.

A custom parser processes decorators, route definitions, and parameter structures.

AI models (LLMs) are used to infer undocumented API behavior.

The AI uses natural language understanding to interpret code comments.

It distinguishes between business logic functions and API endpoints.

For Node.js projects, it detects Express router structures and middleware chains.

For Python projects, it identifies Flask route decorators and view functions.

The extracted API details are normalized into a unified internal representation.

A mapping module converts that representation into a valid Swagger schema.

The backend is built using Python + FastAPI for scalability and async processing.

File upload is handled securely with multipart form data and temporary storage.

Uploaded files are unzipped in isolated directories to prevent path traversal exploits.

The system performs code parsing using AST (Abstract Syntax Tree) analysis.

The AI inference module runs asynchronously to optimize response time.

OpenAI or local LLM APIs may be integrated for semantic interpretation of undocumented functions.

The output JSON includes endpoint descriptions, parameter types, and sample responses.

Each route in the JSON is accompanied by inferred purpose and request schema.

The generated Swagger JSON is validated before being sent back to the user.

Validation uses the swagger-spec-validator or equivalent library.

The system ensures full compliance with OpenAPI 3.0 format.

Users can download the JSON file instantly after generation.

The output can be previewed in Swagger UI if integrated in the front-end.

The architecture follows a modular microservice-style approach.

Core modules include FileManager, CodeParser, AIGenerator, and JSONBuilder.

FileManager handles upload, extraction, and cleanup.

CodeParser performs static analysis and metadata extraction.

AIGenerator uses LLMs to generate missing descriptions or infer function logic.

JSONBuilder compiles the structured Swagger document.

Error handling is centralized with detailed exception logging.

Logging uses Python’s logging module with rotating file handlers.

The backend supports asynchronous file processing using asyncio.

The system is scalable to process large zip files in parallel.

Each file is processed as an independent task in the event loop.

Redis or Celery can be integrated for distributed task management.

Database (optional) stores processing history and user requests.

MongoDB or Supabase can be used for persistent storage if needed.

API keys or user tokens can be added for authentication.

The AI component can run locally or through an API call to GPT-based models.
